# 2026-11-07 运行效率检查与优化

本轮检查原生应用的启动与数据恢复、教务查询和搜索、周课表索引、主页页面切换、课程详情玻璃动画、小组件广播与课程倒计时通知。保留现有视觉、课程时间规则和动画曲线。

## 已修改

- **课程详情动画**：圆角改为稳定的 Shape，在绘制轮廓时读取弹簧状态。移除组合阶段逐帧读取圆角导致的详情子树重组；圆角仍按玻璃采样密度缩放，避免低分辨率取景时变成椭圆。
- **主页组件展开**：同一动画帧的测量、布局和绘制共用窗口边界、轮廓及工作缓冲，减少重复几何对象与边界计算。
- **教务搜索**：每份响应只建立一次规范化文本索引；关键词每次输入只解析一次；空查询直接复用记录。旧查询每 64 条检查取消，避免已失效的筛选继续运行。
- **周课表索引**：按课程的教学周直接分桶，替代 60 周 × 7 天的全量过滤，保留课程顺序和共享课程块。
- **设置与课程快照**：批量设置一次校验和写入，共用锁防止后台刷新覆盖界面设置；内容相同跳过磁盘提交；纯界面设置不再重建课程通知。前台恢复、权限变化和必要的通知更新保留。
- **桌面小组件**：修复调整尺寸、停用和恢复广播经过系统回调后又额外刷新一次的问题。
- **倒计时通知**：每次接收新通知只恢复一次 Builder，逐秒只更新标题；缓存系统服务，每次 tick 只读取一次亮屏状态。保留原调度、锁屏暂停和结束清理逻辑。

## 真机对比

同一台 1216 × 2640 OnePlus、竖屏约 90Hz，使用独立 benchmark 包的合成课表和查询记录。预热后执行相同的快速打开/返回、滚动及翻周操作；测量窗口内不截图、不录屏、不执行 UI 树检查。

下表的“截止时间错过”是 Android `Number Frame deadline missed / Total frames rendered`，并非所有掉帧现象的统一定义。P95 为系统 `gfxinfo` 报告的帧耗时。

| 场景 | 优化前截止时间错过 | 优化后截止时间错过 | P95 前 → 后 |
| --- | ---: | ---: | ---: |
| 主页快速打开/返回，首轮 | 7 / 292（2.40%） | 9 / 303（2.97%） | 31 → 31 ms |
| 主页快速打开/返回，复核 | 6 / 304（1.97%） | 6 / 311（1.93%） | 27 → 28 ms |
| 主页滚动 | 0 / 532（0%） | 2 / 531（0.38%） | 22 → 22 ms |
| 课程状态详情开合 | 3 / 305（0.98%） | 0 / 324（0%） | 24 → 21 ms |
| 周课表连续翻页 | 21 / 488（4.30%） | 19 / 529（3.59%） | 17 → 17 ms |

课程状态面板的本轮帧耗时有所降低；主页快速打开在两轮之间波动，没有证据表明取得稳定的帧率提升。旧版 `legacy janky` 统计在玻璃交互中仍较高，不能将本表解释为全场景稳定 90fps。原始统计和有界测试脚本保存在本机忽略目录 `native/artifacts/optimization-*`。

全屏液态轮廓接近终点时的稠密 Gaussian 场仍是较重的计算。此次保留原采样与融合形状，未通过降低视觉质量来换取测试数字。实时通知的逐秒行为未在有课状态下重新触发验证；本轮对该路径的验证为编译与代码审查。

临时 benchmark 应用已移除，用户课表和账号数据保留。
